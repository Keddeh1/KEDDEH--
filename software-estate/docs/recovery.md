# Recovery and unresolved dependencies

Restore a damaged working file from its exact preserved original, then reapply the documented bounded patch and regenerate derivatives. Verify SHA-256 and byte length before and after restoration. Do not restore from a screenshot, a similarly named carrier or a historical embedded PASS receipt. Preserve current user changes before rebuilding a working tree.

StoreSpace and ServerSpace are separate original applications whose Library package access remains pending. Neither package was acquired in this estate. Their component-index records intentionally contain no invented source path, digest or capability. Acquisition requires authorization for the correct source package, then consumer-local materialization and integrity verification.

HCF is a different case: the standalone original is preserved, and a captured older entrypoint plus served module/source map provides a recovery candidate. [Independent HCF checks](../evidence/independent-hcf-recovery-verdict.json) establish custody and a matching source-map derivative, but not execution or exact newer lineage. The candidate contains 709,628 bytes of TypeScript; an HTML parser found 80 capture DOM IDs versus 96 standalone IDs, with 65 common. Overlap supports lineage only.

Eleven declared local dependencies remain missing:

- `./firebase-applet-config.json`
- `./firebase-setup`
- `./src/adr-registry`
- `./src/apex_processor`
- `./src/braink-sectors`
- `./src/governance-scheduler`
- `./src/pixel-analyzer`
- `./src/provider-hypervisor`
- `./src/substrate_memory.ts`
- `./src/topology-validator`
- `./substrate_effect`

Matching package metadata is also unavailable. Do not invent Firebase configuration, substitute generic modules, or present the candidate as the exact standalone. Preserve `originals/hcf-recovery` and `working/hcf-recovered` independently. Recovery completes only when authorized sources resolve the missing imports, lineage is reconciled and the resulting application has independently observed execution evidence.

For browser failures, first distinguish blocked external dependency, missing host bridge, denied storage, worker policy, actual runtime exception and harness error. Retain the failing result before repair. Reproduce only with disposable data; do not recover user browser profiles or credentials into this test package.
