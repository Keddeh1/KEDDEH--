Formal introduction

This edition preserves and develops Aboudy Keddeh's HTML software estate as independently identifiable software carriers. It provides a navigable account of what is present, how the inspected mechanisms work, what has changed, and which assertions still require execution evidence or missing inputs. The preserved set consists of ten Drive HTML originals and seventeen GitHub source files pinned to 09f45187dbec29ebe63153f916b67505452dc136. Their exact names, lengths and SHA-256 values are in the component index.

The estate uses documents as executable carriers, DOM structures as state in particular KEX machines, logical routes to identify resident applications, browser storage to retain local state, and host adapters to cross into browser or external execution services. Those mechanisms must be assessed individually. A resident route, a rendered projection, a worker capability probe and an externally completed operation are different observations.

BRAINK is not a replacement name for StoreSpace, ServerSpace, HCF, AetherOS or the public frontage. IL-LLM language objects and projection semantics are distinct from BRAINK runtime execution. KEX state geometry is distinct from a VFS storage API. The standalone managed-VFS AetherOS is also distinct from the smaller GitHub AetherOS asset. The source filenames and embedded historical labels can disagree; both are retained, with no silent historical renaming.

This is an architecture and development dossier, not a scientific validation, benchmark publication, security certification or deployment announcement. Evidence separates inherited reports, inspected code, locally reproduced checks and outstanding browser qualification. Recovery identifies the missing originals and the incomplete HCF candidate. Use the monograph for mechanisms and the development guide for reproducible work.
