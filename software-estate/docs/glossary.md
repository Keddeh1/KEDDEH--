# Controlled glossary and definitions

Definitions describe the inspected estate's usage. A declared role does not establish every intended capability. Original user terminology is retained rather than expanded into invented acronyms.

| Term | Controlled meaning in this dossier | Provenance / boundary |
| --- | --- | --- |
| BRAINK | Named runtime/application family; R14 carries resident programs and projects logical routes | R14 `KEDDEHVolume`, `KEDDEHProjectionBus`; [repair account](../development/r14/README.md) |
| IL-LLM | Linguistic/contextual objects, working memory and ledger-bound projection semantics in user space | V11-named Drive carrier, `project`, `renderInspector`, lexical registration; not evidence of trained model inference |
| KEX | Source-defined machine, address and carrier terminology; retain source meaning per component | Computer Stack v10 and Warehouse Fabric v7.1 custom DOM elements |
| State geometry | Addressable axes/origin/lane/extent/revision relationships represented in KEX DOM state | `kex-fabric`, `kex-x`, `address`, `projection`; not physical geometry qualification |
| Canonical state | Authoritative state representation of the particular runtime | Warehouse Fabric declares live DOM/table authoritative; do not generalize to all apps |
| Carrier | Concrete HTML/document or other representation carrying a logical component | R14 resident payloads and Governed Estate logical/carrier records |
| Projection | View of a logically identified object/application | `srcdoc` resident rendering and IL-LLM human/machine/proof/source views |
| VFS | Virtual filesystem model belonging to a named runtime | R14 P07 `KEXVolumeFS`; managed AetherOS base/overlay are separate implementations |
| Host adapter | Boundary binding logical operations to browser/host capabilities | P19 `KEXHostAdapters`; API presence is not successful execution |
| Checkpoint | Named captured state serialized by a runtime | P19 stores VFS/hardware/network summaries; restore explicitly applies VFS when available |
| Receipt | Structured actor or observer record of an operation | P19 and AetherOS schemas differ; actor receipt is not independent approval |
| Managed policy | Application-level mutation rules for protected VFS prefixes | AetherOS `aetherAuthorize`, groups and protected prefixes; not OS privilege |
| Provider | Bound execution service needed for a specific language/host operation | Computer Stack runtime declarations and developer workbench |
| StoreSpace | Distinct user application; original input unresolved | User-supplied identity; no implementation inspected in this estate |
| ServerSpace | Distinct user application; original input unresolved | User-supplied identity; no implementation inspected in this estate |
| HCF | Preserved workstation identity plus separately identified recovery candidate | Original `hcf_workstation.html`; [HCF evidence](../evidence/independent-hcf-recovery-verdict.json) |
| Public frontage | Repository website/deployment surface distinct from standalone estate | Repository `src` and root application definition; not browser-qualified here |
| Independent evidence | Observation made outside the app's own success assertion, with scope recorded | Test harness/readback/independent parser; see [evidence register](evidence-register.md) |
| Qualified capability | Capability supported by a matching tested mechanism and outcome under stated conditions | Editorial convention for this dossier; not an invented source approval |
