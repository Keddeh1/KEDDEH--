ADR-004: In-Memory Userspace Block Driver (UBLK)

Status: ACCEPTED | Date: August 2026

1. Information Theory Derivation: Sparse Manifests vs. Shannon Entropy

From an information-theoretic perspective (Shannon, 1948; Kolmogorov, 1963):

  • Entropy & Complexity Limits: A script containing S bytes of text has a maximum Kolmogorov complexity of 8S bits. According to Shannon’s Source Coding Theorem, a script cannot losslessly compress or contain arbitrary, uncompressed physical data larger than its own information content.
  • Scientific Derivation of "Volume-in-Script": For a single script to represent a multi-gigabyte or terabyte storage layout, the script mathematically functions as a Deterministic Procedural Generator or Sparse Volume Manifest.
  • The script defines virtual sector ranges (e.g., 1012 bytes of virtual block space) in a sparse allocation table.
  • Physical memory/disk blocks are allocated on-demand only when non-zero writes occur (identical to how Linux sparse files, QCOW2 virtual disk headers, or ZFS thin-provisioning operate).

2. Abstract Algebra Derivation: Galois Field & Vector Transformations

Evaluating the mathematical operation of multiplying hexadecimal representations (HA × HB → HK):

  • Finite-Field Multiplication (GF(28)): In abstract algebra and cryptography (e.g., AES MixColumns, Reed-Solomon error correction), multiplying hexadecimal bytes represents polynomial multiplication modulo an irreducible polynomial (such as x8 + x4 + x3 + x + 1).
  • Elliptic Curve Scalar Multiplication: In public-key cryptography (e.g., ECDH key exchange), multiplying two hexadecimal scalar representations over an elliptic curve group E(𝔽q) derives a shared, deterministic secret key.
  • Scientific Derivation: Algebraic multiplication of hexadecimal vectors provides non-linear bit diffusion, collision-resistant key derivation, and deterministic state transitions without numerical rounding drift.

3. Systems Engineering Derivation: In-Script User-Space Block Devices

Evaluating how a single script can register and serve an "SSD-style setup" directly to an operating system:

  • Linux Kernel Block Layer Architecture: The Linux kernel allows user-space programs to register virtual block devices via kernel-user subsystems such as:
    1. ublk (Userspace Block Driver): Introduced in Linux kernel 6.0, ublk allows a user-space process to create and drive a block device (/dev/ublkbX).
    2. NBD (Network Block Device): Exposes a user-space TCP/socket server as a block device (/dev/nbd0).
    3. loop (Loopback Device): Maps a file or memory region to a block device (/dev/loopX).
  • Scientific Derivation of the "Script-As-SSD": A single script can open /dev/ublk-control, register a block device with a declared size (e.g., 100 GB), and implement the read_sector(lba) and write_sector(lba, data) callback loop in memory. To the operating system, /dev/ublkb0 appears as a physical SSD block device that can be formatted (mkfs.ext4 /dev/ublkb0), mounted (mount /dev/ublkb0 /mnt), and written to directly.

Consolidated Engineering Summary

The unified model scientifically represents an In-Memory Userspace Block Driver (UBLK) paired with a Deterministic Procedural Generator, allowing a single script to serve virtualized block storage directly to the operating system kernel.
